# Dataset Inspection and Authoritative Schema Mapping

## 1. Overview and Authoritative Principles

This document defines the schema mapping, entity relationships, identifier contracts, and benchmark safety rules for the **TigerGraph Agentic Fraud Investigation Agent (HHGOA)**.

In accordance with [AGENTS.md](file:///Users/kishan/All-Project/Projects/TigerGraph-Agentic-Fraud-Investigation/AGENTS.md) and [GEMINI.md](file:///Users/kishan/All-Project/Projects/TigerGraph-Agentic-Fraud-Investigation/GEMINI.md):
1. **The dataset README is authoritative**: Field meanings are strictly grounded in dataset documentation without inventing unobserved fields.
2. **Bank Risk Score is a signal, not ground truth**: The `bank_risk_score` is treated as an input feature for evidence synthesis, never as an oracle label.
3. **No Benchmark Leakage**:
   - Zero hardcoding of benchmark case IDs (`CASE_001` ... `CASE_020`).
   - Zero branch logic based on benchmark case numbers.
   - Benchmark cases must run through the exact same LangGraph investigation pipeline as real-time triggers.
4. **Historical Cases as Precedent, Not Proof**:
   - Past resolved cases provide contextual precedents and pattern comparisons.
   - Cleared and confirmed-fraud historical cases are equally accessible for precedent analysis.

## 3. Entity Attributes and Types

### 3.1 Transaction Entity
- `transaction_id` (String, PK): Unique transaction identifier.
- `amount` (Float): Transaction monetary amount.
- `currency` (String): ISO currency code (default: USD).
- `timestamp` (Timestamp / ISO-8601): Event occurrence time in UTC.
- `bank_risk_score` (Float, Optional): Continuous signal (0.0 to 1.0) generated by baseline rules/models.
- `channel` (String): Web, Mobile, In-Store, POS, ATM.

### 3.2 Customer Entity
- `customer_id` (String, PK): Unique customer identifier.
- `created_at` (Timestamp): Date account relationship was opened.
- `risk_tier` (String): Standard, High-Value, Watchlist, etc.

### 3.3 Account / Card Entity
- `account_id` (String, PK): Bank account or tokenized card number.
- `account_type` (String): Checking, Savings, Credit, Debit, Prepaid.
- `status` (String): Active, Suspended, Restricted, Closed.

### 3.4 Device Entity
- `device_id` (String, PK): Hardware identifier or device fingerprint.
- `device_type` (String): Mobile (iOS/Android), Desktop, Tablet.
- `first_seen_at` (Timestamp): First appearance in transaction logs.

### 3.5 IP Address Entity
- `ip_address` (String, PK): IPv4 or IPv6 client address.
- `asn` (String, Optional): Autonomous System Number / ISP.
- `country_code` (String, Optional): Geolocation country code.

### 3.6 Merchant Entity
- `merchant_id` (String, PK): Merchant identifier.
- `merchant_name` (String): Merchant name or category.
- `merchant_category_code` (String / MCC): Standard 4-digit MCC code.

### 3.7 Historical Fraud Case Entity
- `case_id` (String, PK): Case reference identifier.
- `opened_at` (Timestamp): Timestamp investigation was initiated.
- `closed_at` (Timestamp): Timestamp investigation concluded.
- `outcome` (Enum): `FRAUD_CONFIRMED`, `FALSE_POSITIVE_CLEARED`, `INCONCLUSIVE`.
- `primary_typology` (String): e.g., Account Takeover (ATO), Mule Ring, Authorized Push Payment (APP).
- `summary` (String): Text summary of analyst findings and evidence.

## 5. Benchmark Safety & Leakage Prevention Rules

1. **Benchmark Isolation**:
   - Benchmark case data must never be mixed into historical training sets (e.g., LightGBM risk models).
   - Only historical resolved cases with historical outcomes occurring strictly prior to the benchmark period may be used for precedent retrieval.
2. **Ground Truth Distinction**:
   - The field `bank_risk_score` is strictly an auxiliary signal.
   - Ground truth fraud cannot be assumed from high risk scores or suspicious attributes alone.
3. **Execution Invariance**:
   - Running the benchmark suite runs `scripts/run_benchmark.py` calling the unified `InvestigationService` and LangGraph state graph.
   - Answer artifacts are generated directly from the case state and verified against benchmark schema criteria.
